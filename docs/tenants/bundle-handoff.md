## 3. HaiGO を他社に出すときの論点

1. **HaiGO は自前のDBを持たず、WTS のDB `twinklemark_wts` に同居している。**
   HaiGO ADR-0001 D1「B案＝WTSのDBを正本として共有」。`dispatch_*` 8テーブルが HaiGO のもの。
   WTS のテナント基盤スキーマからは外してあるので、HaiGO を同梱するなら戻す
   （`wts/sql/tenant_base/000_schema.sql` のヘッダに明記済み）。
2. **他社提供は HaiGO 自身の設計記録で保留。** HaiGO ADR-0001 D12 が `proposed`
   ＝「Smiley専用で開始し、Phase3 で外販可否を判断」。今回の話はこの判断の前倒し。
3. **Xenia 同期を必ず切る。** HaiGO は顧客登録時に Smiley の顧客マスタ Xenia へ同期する
   （`api/customers.php` の upsert 経路）。他社テナントで動くと、**他社の利用者の個人情報が
   Smiley の顧客DBに流れ込む**。
4. **TimeTree 連携も切り替えが要る。** Smiley の旧運用向け（12ファイル）。
5. **配置と設定が1系統に固定。** 本番は社内ゾーン `twinklemark.xsrv.jp/haigo/`、
   .env は `~/private/env/prod/haigo/` 固定。会社ごとに置く仕組みが無い。

## 4. 料金シミュレーターを他社に出すときの論点

静的HTML1枚でDBなし。会社ごとに次の値を差し替えれば配れる。
**今のヒアリングシートにはこの項目が無い**ので、10月に渡すならシート送付前に足す。

- 運賃: 初乗り、距離加算、時間加算
- 機材料金: リクライニング車椅子、ストレッチャー
- 介助料: 室内介助、院内介助、階段介助、外出付添
- 表示: 社名、ロゴ、電話番号

HaiGO が要る会社かは、シートの「現在の予約管理の方法は？」で見当がつく。

## 5. WTS 側で済んでいること・残っていること

済み（詳細は `docs/tenants/README.md`）:
- テナントDBの作成と権限付与を XServer API で自動化（`scripts/create_tenant_db.py`）
- 空DBから立てる基盤スキーマと初期データ（`wts/sql/tenant_base/`）。空DBへ実投入し、
  雛形元とテーブル・列構成・トリガー・外部キーが一致することを確認済み
- 構築スクリプトの不具合3件を修正（起動直後に終了・鍵パス・平文パスワード）
- 聞いた事実と進捗の器（`docs/tenants/_pending/`）

残り:
- **構築の通し稽古は未実施。** DB作成と基盤スキーマ投入は検証済みだが、コードのコピー・
  設定ファイル生成・管理者作成の工程は一度も通していない。検証用DB `twinklemark_wtsverify`
  （保持と決定済み）を使えば事前に試せる。ただし顧客向けドメインに検証用の画面が1つできる
- **ヒアリングシートは未送付。** 10月開始ならここが最も遅れやすい

## 6. 置き場の提案

- **Clio に置く**: 3製品にまたがる開設手順書と、各製品の開設を順に呼ぶ取りまとめスクリプト
- **各 repo に残す**: 製品固有の開設手段。WTS は §5 の一式がそのまま部品になる

## 7. 別件（Clio 側で拾ってほしいもの）

- **clio の `scripts/mneme_api.py` 31行目が、読み込み時に `sys.stdout` を差し替える。**
  ガードが無いため、パイプやリダイレクト時にそれ以前の出力が黙って消える。
  `xserver_client` 経由で API を1回呼ぶだけで起きる。直すなら `if __name__ == "__main__"` の中へ
  移すか `reconfigure` を使う。WTS 側は呼ぶ側で回避済み（`create_tenant_db.py` の `_say()`）
- **テスト環境の `twinklemark.xsrv.jp/Smiley/taxi/simulation/` は古い WTS の複製。**
  2026-04-16 から更新が無いのに Smiley 本番DB `twinklemark_wts` に接続している。
  料金シミュレーター（`tw1nkle.com/Smiley/tax/simulation/`）と名前が紛らわしい
- **Lino テナントが本番より古い。** 画面コードで差分あり、DB に `vehicles` の form21 系4列が無い
