## 先に見てほしいもの（重い順）

### 1. 本番で開けない・必ず失敗する（実物で確かめた）
- **事故管理 `accident_management.php` は全テナントで開けない。** `users.role` 列が無く 128 行目で致命的エラー（2026-11-18 に kinki のDBで実描画して確認）。`accidents` 表にも画面が使う8列が無い（kinki・lino・fmb で確認）。事故記録は3テナントとも0件＝今まで誰も使えていない。

### 2. 取り返しがつかない（データが消える・本番記録が集計から外れる）
- **データ管理 `data_management.php`**: 既定値のまま「期間指定でマーク」「本番運用開始」を押すと、確認1回で本番の記録が見本扱いになり集計から外れる。画面から戻す操作が無く、続けて「サンプルデータ削除」で物理削除まで行ける（C-1〜5）。3テナントとも見本扱いの乗車記録は現在0件（＝まだ事故は起きていない）。
- **車両編集がメーターを古い値で上書き**（C-7）、**定期点検の登録で現在メーターが巻き戻る**（D-13）＝入庫で直したメーター巻き戻りと同じ類型。
- **乗車記録の削除**は確認1回で物理削除・他人の当日分も消せる（A-23）。
- **自分の無効化・最後の管理者の降格が通る**（C-6）。

### 3. きっかけと同じ型（保存してから弾かれる・入力が消える）
- **乗務後点呼**: 乗務前点呼が無いと、全部入れて保存してから弾かれ白紙に戻る。日付が常に当日で、0時を過ぎると必ず弾かれる（A-3・A-4）。
- **入庫記録の修正**: 費用が10円単位でないと保存できない／弾かれた理由が「undefined」と出る（A-1・A-2）。
- **現金カウント**: 期間が重なっていても数え終えて保存してから弾かれる。運転者や日付を変えると数えた枚数が消える（B-8・B-9）。
- **保存が通らないと入力が全部消える**画面が多い（点検・点呼・乗車記録・苦情・院内介助・ユーザー・車両・定期点検・事故・指導監督）。
- **開いたまま時間切れで入力が消える**（全画面共通・`includes/session_check.php`）。

### 4. 二重登録・押し間違い
- 保存後の再読込で同じ記録がもう1件入る: 乗車記録（売上が二重）・苦情・院内介助・場所・事故・定期点検・指導監督。
- 確認でキャンセルすると保存ボタンが「保存中...」のまま固まる（共通JS・A-16）。
- 反転式の切替（集金チェック・輸送分類の有効/無効）は、古い画面や再読込で意図と逆になる（B-5・C-10）。

### 5. 法定記録の中身
- アルコール測定値の既定が 0.000 で、測らずに登録できる。必須の確認項目を1つも付けずに完了扱いになる（A-12・A-13）。
- 定期点検は26項目を1つも押さずに「合格」で登録できる（D-12）。
- 日常点検の古い下書きを復元すると日付が昨日に戻り、昨日付の記録ができる（A-9）。
- 「修正」で日付・運転者を変えると別の記録ができる（A-10）。

### 6. お金の決まりが複数箇所にある（規約10）
- 現金売上の式が4か所で違う／基準おつり18000が3か所に直書き／現金カウントの合計は画面の計算をサーバーがそのまま信用（B-2〜4）。

### 7. 使われていない・壊れているコード
