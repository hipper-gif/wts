## Context（背景・なぜ決める必要があるか）

WTS を新しく使う会社が1社決まった（2026-09-18 時点で会社名は未ヒアリング）。3社目のテナントになる。

開設の道具は一式そろっているように見えたが、実際に通せる状態ではなかった。調査で分かったこと:

1. **空のDBからスキーマを作れない。** `wts/sql/` の連番マイグレーションは `003_` から始まり、
   土台となる `users` / `vehicles` / `ride_records` 等を作るSQLが repo に無い。
2. **マイグレーション履歴が実態とずれている。** `vehicles` の form21 系4列
   （`is_wheelchair_compatible` 他）は本番に存在するが `migration_history` に無い。
   連番SQLの積み上げでは現行スキーマを再現できない。
3. **`provision_tenant.sh` は起動直後に死ぬ。** 初期パスワード生成の
   `cat /dev/urandom | tr -dc ... | head -c 12` が `set -o pipefail` 下で
   SIGPIPE を拾い、終了コード141でスクリプトごと終了していた（再現確認済み）。
4. **SSH鍵のパスが実在しない。** `C:/projects/wts/twinklemark.key` はこのマシンに無い。
5. **DBパスワードがスクリプトに平文で直書き**されていた（社内規約の禁止リスト違反）。

つまり「Linoのときに動いた手順」は再現できる状態で残っていなかった。

## Decision（確定した主要決定＝1決定1行）

| # | 決定 | 理由（1行） | 出典 |
|---|------|------|------|
| D20 | **空DBの土台は稼働中DBから取った `wts/sql/tenant_base/000_schema.sql` を正本とする**（37テーブル・構造のみ） | 連番マイグレーションでは現行スキーマを再現できないため | 2026-09-18 調査 |
| D21 | **配車機能 `dispatch_*`（8テーブル）はテナントに配らない** | Smiley専用機能でLinoにも配っていない。既存の姿を踏襲する | 実機比較 |
| D22 | **会社共通の初期データは `001_seed.sql` に持ち、会社固有の値は空で入れる** | `company_info` の id=1 行が無いと構築スクリプトが黙って何も入れない | provision Step 5.5 の構造 |
| D23 | **DB認証情報はスクリプトに書かず、環境変数か稼働中 `.env` から取る** | 秘匿情報の直書き禁止（CLAUDE-global 禁止リスト） | 社内規約 |
| D24 | **Xserver パネルでの DB 作成は人手の前提作業として手順に明記する** | SSHのDBユーザーに `CREATE DATABASE` 権限が無い（`GRANT USAGE ON *.*` のみ） | 2026-09-18 権限確認 |

## Consequences（この決定で何が変わるか・トレードオフ）

- 良くなること: 会社名さえ決まれば、パネルでのDB作成1回を挟んでスクリプト1本で開設できる。
  聞いた事実とその会社の進捗は `docs/tenants/<テナントID>/` に残り、次の会社でも同じ手順が使える。
- 引き受けるコスト・制約: `000_schema.sql` は**稼働中DBのスナップショット**なので、
  本番スキーマを変えたら取り直す必要がある（放置すると腐る）。取り直し方はファイル冒頭に書いた。
- **未完（この決定だけでは開設できない）**: 空DBに対する投入試験は**未実施**。
  DBを作れるのがパネルだけで、検証用のDBを用意できなかった。SQLはサーバー側パーサで
  構文・テーブル・列の実在まで検証済みだが、実地で通すのは最初の1社が初回になる。
- 捨てた選択肢と理由:
  - *連番マイグレーションに 001/002 を書き足して土台を作る* — 実スキーマとの乖離
    （form21 列など履歴に無い変更）を手で埋め戻すことになり、正しさを担保できない。
  - *Lino のDBを雛形にする* — Lino は本番より古く、`vehicles` の form21 系4列が無い。
- 副作用: `provision_tenant.sh` の SIGPIPE バグ修正により、そもそも動かなかった
  スクリプトが動くようになった。Lino 開設時に何が実行されたのかは追えていない。

## 未解決（この ADR の範囲外として残すもの）

- `scripts/backup_wts.sh` と `scripts/setup_lino_data.php` の平文DBパスワード。
  バックアップの定時実行を壊す恐れがあるため今回は触っていない。
- Lino テナントが本番より古い件（コード301行差・DBスキーマ差）。揃えるかは別途判断。
