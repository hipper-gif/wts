# ADR-0013 点呼は測定値を既定で入れず、必須の確認項目を付けないと登録できない

- 状態: accepted（2026-11-18）
- 決めた人: 杉原氏（A案・B案を示し「進めて下さい」＝勧めたA案）
- 関連: 全画面点検の5番（A-12・A-13・A-22・D-12・A-9・A-10）、ADR-0012、ADR-0002

## 背景
- 乗務前・乗務後点呼のアルコール測定値は最初から 0.000 が入っていて、測らずに登録できた。記録からは測ったかどうかが分からなかった。
- 「（必須）」と書いた確認項目に検査が無く、1つも付けずに完了扱いで登録できた。
- チェックの四角そのものを押すと、枠の処理と二重に切り替わって付かなかった（コード読みの所見）。
- 定期点検は26項目を1つも押さずに「合格」で登録できた。
- 日常点検は、昨日の途中の下書きを今日に復元すると昨日付の記録ができ、「修正」で点検日を変えると別の日に複製ができた。

## 決定
1. アルコール測定値の既定値をやめる（空欄）。0 だった時は「0.000設定」を1回押す。空のままでは登録できない。
2. 必須の確認項目（乗務前＝健康状態・運行前点検・免許証／乗務後＝健康状態・酒気薬物・事故違反・車両）は、付けないと登録できない。画面で送る前に止め、サーバーでも同じ検査をする。項目の決まりは `getRequiredDutyCallChecks()`／`validateDutyCallInput()`（functions.php）1か所。
3. チェックは、四角・ラベル・枠のどこを押しても1回だけ切り替わる（`wtsToggleCheckFromContainer`）。
4. 定期点検は、結果が1つも無い登録を止める。一部だけ未入力の時は、件数を出して確かめる（該当しない項目のある車両があるため、全項目必須にはしない）。
5. 日常点検は、別の日の下書きを使わない（開いた時に捨てる）。「修正」で点検日は変えられない（間違えた日付の記録は削除して登録し直す）。
6. 自前の JS・CSS は URL に更新時刻を付ける（`wtsAssetUrl`）。端末に残った古いファイルで、新しい検査が効かない・チェックが動かないことを防ぐ。

## 却下した案
- 今のまま（B案）: 手間は増えないが、測った・確かめたという操作が記録に残らない。
- 測定値が 0.15 以上の時に登録を止める: 止めた後の運用（乗務させない・再測定）が決まっていない。未決のまま残す。
- 定期点検を全26項目必須にする: AT車のクラッチなど該当しない項目がある。「該当なし」を足すかは別途。

## 見張り
- 点呼の件数が減っていないか（登録が面倒で入れなくなっていないか）。ダッシュボードの点呼漏れ警告。
- 運転者の実機で「0.000設定」と必須4項目が押しやすいか（未確認）。
