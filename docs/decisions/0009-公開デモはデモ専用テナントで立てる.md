## Context

Astella の LP・`/works/` に「押したら動く」デモを載せたい（2026-10-08 杉原氏）。WTS はテナント開設の手順（ADR・`docs/tenants/README.md`）が確立しているので、
1社増やすのと同じ手順でデモを作れる。ただし公開デモは**誰でも書き込める**ため、本番と同じ作り方のままでは次の穴がある（実査で確認）:

- DBユーザー `twinklemark_taxi` は全テナント共有 → デモの `.env` に本番DBにも届く資格情報が入る
- 管理者を渡すとユーザー削除・データ管理（ALTER）まで誰でもできる
- 書き込まれたデータが残り続ける

## Decision

**テナント `demo`（`/wts-tenants/demo`・DB `twinklemark_wtsdemo`）を立て、①デモ専用DBユーザー ②一般ユーザーで自動ログイン ③毎朝作り直し の3点を足す。**

1. **DBユーザーはデモ専用 `twinklemark_wdmo`**（XServer API で作成・権限は `twinklemark_wtsdemo` のみ・パスワードは Mneme credentials `mysql-twinklemark_wdmo`）。共有ユーザーを使う開設手順の既定から外す唯一のテナント。
2. **自動ログインは `.env` の `DEMO_LOGIN_ID` がある時だけ**（`index.php`）。対象は `permission_level='User'` に限る＝Admin を指しても入れない。本番・他社テナントの `.env` には書かない。HaiGO も同じ仕組み（HaiGO `api/config.php` の `haigo_demo_autologin()`・`~/private/env/prod/haigo-demo/.env`）。
3. **毎朝 4:20 に作り直す**（server crontab → `~/private/demo/reset_demo.sh`＝repo `scripts/demo/reset_demo.sh`）。全テーブル削除 → 開設直後の状態 `~/private/demo/wtsdemo_base.sql` → `wts/tools/demo_seed.php` で「今日」基準の架空データ。
4. データはすべて架空（会社＝みほん介護タクシー・利用者8人・施設6か所・電話は 000-0000-0000）。`demo_seed.php` は DB名が `twinklemark_wtsdemo` かつ `DEMO_LOGIN_ID` がある時しか動かない。
5. HaiGO の cron 巡回（`~/private/haigo_tenants.txt`）には**載せない**（リマインダー等を動かさない）。

## Consequences

- 良くなること: LP から押して動く WTS＋HaiGO を見せられる。デモからは本番DBに届かない。荒らされても翌朝戻る。
- 引き受けること:
  - `admin` は開設時の乱数パスワードのまま誰にも渡さない（使わない）。
  - **`demo` は `tenants.conf` に載っている＝`deploy_all_tenants.sh` の配布先に入る。** 配布元は Smiley本番のコードなので、自動ログイン（`index.php`）が本番に配られる前に一括配布すると、デモの自動ログインが消える。→ 本番へ `index.php` を出すまでは、一括配布の後に demo へ `index.php` を置き直す。
  - スキーマが変わったら base を取り直す（`reset_demo.sh --rebase`）。
- 捨てた選択肢:
  - 本番DBに「デモ会社」の行を作る: 誰でも本番DBに書ける・テナント分離のバグ1つで実データが見える。
  - 共有DBユーザーのまま: デモの `.env` から本番DBに届く。
  - 画面だけのモック: ADR-0001（astella）で「押しても動かない方がスクショより悪い」として却下済み。
