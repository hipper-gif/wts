# ADR-0011 入庫漏れは出庫画面で一緒に登録する／入庫保存後に勝手に乗務後点呼へ移らない

- 状態: accepted（2026-11-18）
- 決めた人: 杉原氏（「入庫してないと出庫できないのが不便すぎる」「入庫だけ保存したら乗務後に飛ぶのが分かりにくい」）。直し方は Claude 案
- 関連: 2026-10-20 の根本対策（796e6e6＝前回入庫が無い車両は出庫を止める・当日入庫後は乗務後点呼へ自動で移す）の2点を置き換える。ADR-0002（事後登録方針）

## 背景
2026-10-20 の対策は、入庫漏れを残さないために「前回の入庫が無い車両は出庫を保存時に弾く」「当日の入庫を保存したら乗務後点呼へ自動で移す」とした。現場では、
- 出庫を全部入れて保存してから弾かれ、入庫画面へ行き、出庫画面へ戻って入れ直す。前の運転者の入庫漏れだと、入庫時刻が分からず出庫そのものができない。
- 入庫を保存した途端に別の画面（乗務後点呼）になり、入庫が保存されたのか・今どこにいるのかが分からない。

## 決定
1. 入庫漏れの車両を出庫画面で選ぶと、その場に「前回の入庫」欄（入庫日・入庫時刻・入庫メーター）を出し、出庫と同じ1回の保存で両方登録する。別画面へ行かせない。
2. 入庫メーターの既定は「今回の出庫メーターと同じ値」。入庫後に車を動かしていた場合だけ人が直す。
3. 入庫時刻が分からないとき（前の運転者の漏れ等）は「あとで登録する」を選べば出庫だけ通す。入庫漏れはダッシュボードの警告に残り続ける。入庫メーターは失われない（次の出庫メーターが前回入庫時点の実測値）。
4. 出庫画面から登録した入庫は `remarks` に経路を書く。入庫日が登録日より前なら「【YYYY-MM-DD 事後登録】」を付ける（ADR-0002 D13）。
5. 入庫の検証と保存は `registerArrivalRecord()`（functions.php）1か所。入庫画面と出庫画面の両方が呼ぶ。同じ出庫への二重入庫はここで止める。
6. 入庫を保存しても入庫画面にとどまる。当日の乗務後点呼がまだなら、保存の知らせの中に「乗務後点呼へ進む」ボタンを出す（自動では移らない）。
7. 出庫の保存が通らなかったときは、入れた値を残して出し直す。

## 却下した案
- 弾くのをやめるだけ（警告のみ）: 入庫漏れがそのまま増える。
- 入庫時刻も機械が埋める: 推定値で法定記録を埋めない（ADR-0002 D12）。

## 見張り
- 入庫漏れ・乗務後点呼漏れの件数（ダッシュボード警告＝`api/dashboard_alerts.php`）。「あとで登録する」や自動遷移をやめたことで増えるなら、この決定を見直す。
