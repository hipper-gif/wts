## Context（背景・なぜ決める必要があるか）

2026-09-11 の実査で、運転者台帳（`users` の拡張項目）が**在籍運転者4名中2名・3項目しか埋まっていない**ことが判明した。適性診断日・健康診断日・雇入日は6名全員が空で、**次回期限の管理が機能していない**。一方 NAS には `運転者台帳テンプレート.xls`（2025-05-09更新）が残っており、紙/Excel運用が併存している疑いがある。

全社規約（CLAUDE-global「データ設計の規約」2条）は「新アプリは独自の従業員マスタを作らず Mneme API を読む」と定めるが、**WTS は Lino へ外販済みで本体コードを変更できない**（ADR-0001 D2）ため、Mneme 参照方式へは切り替えられない。

## Decision（確定した主要決定＝1決定1行）

| # | 決定 | 理由（1行） | 出典 |
|---|------|------|------|
| D17 | **運転者台帳（免許・乗務員証・適性診断・健診・雇入日）の正本は WTS `users` の拡張項目とする** | 期限管理をシステム側で機能させる。読み口を1つに固定する | 施主判断 2026-09-11 |
| D18 | **NASの `運転者台帳テンプレート.xls` は新規更新しない。WTSへ転記後に廃止する** | 二重管理をやめる（二重管理の本質は"変える権利の分裂"） | 同上 |
| D19 | **WTS は「社員identityの正本＝Mneme」規約の例外とする。**WTS `users` は運行管理に必要な範囲のコピーを持ち、全社正本は Mneme のまま | 本体不改造（D2）と規約を両立。ADR-0001 D4（Xeniaミラー方式）と同じ整理 | CLAUDE-global 規約2条 / ADR-0001 D4 |

## Consequences（この決定で何が変わるか・トレードオフ）

- 良くなること: 免許期限・次回適性診断・次回健診がシステム上で期限管理できる（`driver_roster.php` が台帳として使える）。Excelとの突合作業が消える。
- 引き受けるコスト・制約: Mneme との二重入力が残る（本体不改造の代償）。全社の人事情報が変わったとき WTS 側は自動追随しない＝人手で直す前提。
- **未完（この決定だけでは台帳は使えない）**: 在籍4名の実データが未入力。必要なのは ①杉原星・杉原充の免許証番号/種類/有効期限/乗務員証番号 ②全員の雇入日・適性診断受診日・健康診断受診日 ③松本邦康の生年月日（現在 **1912-04-25＝114歳**の明らかな入力ミス）。入力画面は `user_management.php`。
- 捨てた選択肢と理由:
  - **Mneme API 参照に切り替える** → WTS本体不改造（D2）に反するため不採用（D19）。
  - **Excelを正本のままにする** → 期限管理が人の目視頼みで機能しないため不採用（D18）。
