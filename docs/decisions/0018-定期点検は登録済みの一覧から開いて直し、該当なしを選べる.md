# ADR-0018 定期点検は登録済みの一覧から開いて直し・消せる。項目に「該当なし」を選べる

- 状態: accepted（2026-11-26）
- 決めた人: 杉原氏（全画面点検の残りを「③定期点検の一覧・修正・削除の画面」の順で直す、とタスク台帳で決定）。直し方は Claude 案
- 関連: 全画面点検 D-21・D-26・D-27（`docs/investigations/2026-11-18-全画面点検/D-記録簿・帳票.md`）、ADR-0016・0017（日々の記録の直し方）、sql/029

## 背景
- 定期点検は登録する画面しか無く、登録後に間違いに気づいても、一覧・修正・削除がどこにも無かった（D-21）。二重に登録しても消せない。
- 項目の結果は「良好・要注意・不良」だけ。AT車・HV車に無い項目（クラッチ・点火時期・デストリビューター等）は空のままで、未点検と区別できなかった（D-26）。
- 登録できた時に同じ知らせが3回出ていた（D-27）。

## 決定
1. 定期点検の画面の上に「登録済みの定期点検（新しい順・直近30件）」を畳んで置く。1行＝点検日・車両・種類・点検者・総合結果。押すとその記録を同じ画面で開く（`?id=`）。開いている時は、上に「○/○ 車両 の定期点検を開いています」と「新しく登録する画面へ」を出し、ボタンは「変更を保存」になる。
2. 直せる人: 登録した日のうちは誰でも（打ち間違いをすぐ直す）。それより後は管理者だけで、修正の理由が要る（監査ログに残す）。サーバーで確かめる。
3. 消せる人: 管理者だけ。理由を入れ、消す前に記録と項目の両方を控える（`archiveRowsBeforeDelete`・同じ操作番号）。
4. 車両の次回点検日は、その車両で一番新しい定期点検の次回点検日に合わせる（古い日の点検を後から登録・修正・削除しても、新しい点検の予定を戻さない）。現在メーターは大きい方を残す（今までどおり）。
5. 項目の結果に「該当なし」を足す（灰色）。総合結果の判定では数えない（不良があれば不合格、要注意があれば条件付合格＝決まりは `periodicOverallResult` の1か所）。表の列に選択肢を足す（sql/029・新テナントの土台 000_schema も同じ）。
6. 未来の日付の点検は登録できない。車両・点検者は選べる一覧にあるものだけ、走行距離は数字だけを受ける。
7. 登録できた時の知らせは1回だけにする。

## 却下した案
- 一覧を別の画面に分ける: 入口が増える。直したい時は登録の画面に来るので、同じ画面の上に畳んで置く。
- 過去の記録は誰も直せない（日常点検・点呼と同じ）: 定期点検は後からまとめて入れることが多く、登録した日の打ち間違いも直せなくなる。登録した日のうちは誰でもにした。

## 残っていること（この決定の外）
- 「自動入力」ボタンの名前（D-25）・整備事業者名の既定値（D-22）・種類と次回点検日の関係（D-28）。
- 30件より前の記録は一覧に出ない（データ管理・帳票側で見る）。
