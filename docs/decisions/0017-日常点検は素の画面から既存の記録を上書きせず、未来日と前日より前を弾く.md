# ADR-0017 日常点検は素の画面から既存の記録を上書きせず、未来日と前日より前を弾く

- 状態: accepted（2026-11-26）
- 決めた人: 杉原氏（全画面点検の残りを「②日常点検の当日上書きと未来日」の順で直す、とタスク台帳で決定）。直し方は Claude 案
- 関連: 全画面点検 A-6・A-7（`docs/investigations/2026-11-18-全画面点検/A-日次の運転者動線.md`）、ADR-0012・0016（点呼の日付の決まり）

## 背景
- 当日点検済みでも、素の URL を開くと白紙の新規フォームが出る。同じ点検者・車両で登録すると、押す前に何も知らせず既存の記録を上書きしていた（修正回数＋1・「更新しました」）（A-6）。
- 新規の点検日は、未来日でも過去日でもサーバーが確かめずに通していた。過去データの入力は管理者だけ（`mode=historical`）のはずが、通常のフォームで運転者が何日前でも登録できた（A-7）。

## 決定
1. フォームに「新規」か「修正」かの印（`form_mode`）を持たせる。修正は記録を開いて「修正」を押した時だけ。
2. 新規で、同じ点検者・車両・点検日の記録がもうある時は、上書きせずに止める。理由と「登録済みの記録を開く」を出し、入れた値は残す。印の無い送信（配置前に開いていた画面）も新規として扱う＝上書きしない側に倒す。
3. 押す前に知らせる: 新規の画面で、点検者・車両・点検日の組が今日・前日の登録済みと重なったら、車両の欄の下に知らせとリンクを出し、登録ボタンを押しても送らない。
4. 新規の点検日は、未来日は誰も不可。今日と前日は誰でも、それより前は管理者だけ。決まりは点呼と同じ `canRegisterDailyRecordDate`（`functions.php`・ADR-0016 で `canRegisterDutyCallDate` と書いた関数の名前を、日常点検も呼ぶので改めた）。画面の日付欄にも同じ範囲（max・min）を付ける。

## 却下した案
- 重なったら黙って修正として保存する（今まで）: 押す前に分からず、前の点検の結果が消える。
- 重なったら自動でその記録の修正画面へ飛ばす: 入れた値が消える。知らせて、開くかどうかは人が選ぶ。

## 残っていること（この決定の外）
- 古い下書きの復元（A-9）は、点検日を戻さない形に既に直っている。復元した車両が点検済みなら、この決定の知らせが出る。
- 保存後の再読込で修正回数だけ＋1になる件（PRG 無し）。新規の再読込は今回の決定で止まる（上書きしない）。修正の再読込は残る。
