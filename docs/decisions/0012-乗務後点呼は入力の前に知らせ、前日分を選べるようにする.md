# ADR-0012 乗務後点呼は入力の前に知らせ、前日分を選べるようにする

- 状態: accepted（2026-11-18）
- 決めた人: 杉原氏（全画面点検の所見を「順番に進めていい」）。直し方は Claude 案
- 関連: 全画面点検 A-3・A-4・A-43（`docs/investigations/2026-11-18-全画面点検/`）、ADR-0011（同じ型＝保存してから弾かない）、ADR-0002（事後登録）、2026-10-20 の対策（過去日の点呼登録はシステム管理者へ依頼）

## 背景
乗務後点呼の画面は、
- 乗務前点呼が無い運転者でも入力欄と「登録する」が普通に出て、全部入れて保存してから弾かれ、入力が白紙に戻った。
- 点呼日が常に「今日」で、0時を過ぎると当日の乗務前点呼が無いため必ず弾かれた。前日の入れ忘れも画面から登録できず、ダッシュボードの警告は「システム管理者へ依頼」と案内していた（他社テナントでは頼む先が無い）。
- 運転者の欄を替えても画面が読み直されず、上の乗務前点呼の情報は前の人のまま。替えた先に当日の記録があれば黙って上書きした。

## 決定
1. 今日の乗務前点呼が無い時は、画面を開いた時点で知らせ、「乗務前点呼を入力する」ボタンを出す。登録ボタンは出さない（入れてから弾かない）。
2. 点呼日を選べるようにする。今日と前日は誰でも登録できる（日付をまたいだ・翌朝に気づいた）。それより前は管理者だけ。未来の日付は選べない。
3. 過去日の乗務前点呼は画面から登録できないので、過去日は乗務前点呼の記録が無くても乗務後点呼だけ登録できる（その旨を入力の前に出す）。今日の分は従来どおり乗務前点呼が先。
4. 過去日の分を新しく登録した時は、備考の頭に「【YYYY-MM-DD 事後登録】」を付ける（ADR-0002 D13）。測定値や確認項目を機械が埋めることはしない（D12）。
5. 運転者か点呼日を替えたら、その人・その日の画面に読み直す。「修正」を押した後は運転者と点呼日を変えられない。
6. 今日の画面で、昨日乗務したのに乗務後点呼が無い時は「昨日の分を入力する」を1つ出す。
7. 保存が通らなかった時は理由を出し、入れた値を残す。保存・削除の後は画面を出し直す（再読込で二重に保存しない）。
8. ダッシュボードの点呼漏れの警告は、いちばん新しい漏れの日・運転者の画面を直接開く。

## 却下した案
- 乗務前点呼が無くても今日の乗務後点呼を通す: 乗務前点呼は今日なら画面から入れられる。通すと乗務前点呼の漏れが増える。
- 過去日は従来どおりシステム管理者だけ: 他社テナントは頼む先が無く、行った点呼の記録が残らない。
- 0時から朝までは自動で前日扱いにする: 黙って日付が変わると、深夜に始まる乗務で誤った日に付く。人が選ぶ。

## 見張り
- 乗務後点呼漏れの件数（`api/dashboard_alerts.php`）。
- 事後登録の件数（`post_duty_calls.remarks` が「【」で始まる行）。増えるなら、当日のうちに入れてもらう導線を見直す。

## 残っていること（この決定の外）
- アルコール測定値の既定が 0.000・確認項目を1つも付けずに完了扱いになる件（全画面点検の5番）。乗務前点呼と一緒に別途直す。
