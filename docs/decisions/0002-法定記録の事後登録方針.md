# ADR-0002: 法定記録（点呼・入庫）の欠損は事後登録で補正し、根拠を記録内に残す

## Context（背景・なぜ決める必要があるか）

2026-09-11 の本番DB実査で、**乗務後点呼の入力漏れ37件**（2025-07〜2026-08）と**入庫記録の日付欠損1件**（id=224）が判明した。点呼記録は道路運送法上の義務で運輸局監査の対象のため、欠損したまま放置はしたくない。

一方で、後から作った記録を「当初から存在した記録」と区別できない形で入れると、記録全体の信頼性を損なう。また値を推定で埋めると日報の走行距離等が実態とずれる（前例: 2026-09-07分の入庫を推定メーターで登録してしまった）。**「補うが、補ったと分かる形で補う」**を決めておかないと、同じ判断が毎回ぶれる。

## Decision（確定した主要決定＝1決定1行）

| # | 決定 | 理由（1行） | 出典 |
|---|------|------|------|
| D11 | **欠損した法定記録は事後登録で補う**（放置しない） | 監査対象の記録を欠いたままにしない | 施主判断 2026-09-11 |
| D12 | **値は必ず別の一次記録から引く。推定値で埋めない**（点呼時刻＝同運行の入庫時刻、入庫メーター＝翌営業日の日常点検実測値） | 推定で埋めると日報の走行距離が実態とずれる | wts-arrival-backfill-recipe |
| D13 | **`remarks` に「【YYYY-MM-DD 事後登録】」と根拠（引用元テーブル・ID）を必ず書く** | 監査で「後から入れた記録」と説明でき、根拠を追える | 本ADR |
| D14 | **実測値の一次記録が残っていない項目（アルコール検査値等）は、その旨を remarks に明記した上で施主が値を決める。Claude は勝手に決めない** | 実施事実は本人しか知らない。記録の捏造にしないため | 施主判断 2026-09-11（0.000で記録） |
| D15 | **チェック項目は当時の画面に存在した項目だけを立てる**（後から増えた項目に遡って1を立てない） | 当時存在しなかった記録を作らない。実データの月別傾向に合わせる | 本ADR（新5項目は2025-12以降のみ） |
| D16 | **入庫記録を編集したら `is_edited` / `edit_reason` / `last_edited_by` / `last_edited_at` を必ず立てる** | 編集の事実をレコード自身に残す | arrival_records の既存設計 |

## Consequences（この決定で何が変わるか・トレードオフ）

- 良くなること: 欠損37件が埋まり、出庫に対する乗務後点呼の欠落が**0件**になった。事後登録分は `remarks LIKE '%事後登録%'` で全件抽出でき、監査で説明できる。
- 引き受けるコスト・制約: 事後登録のたびに施主確認が要る（D14）。一次記録が無い項目は「実施した前提の値」であり、測定の証跡そのものではない——この限界は remarks に明記して引き受ける。
- 捨てた選択肢と理由:
  - **欠損のまま放置** → 監査で指摘されうるため不採用。
  - **一次記録なしの推定値で埋める** → 記録の信頼性を損なうため不採用（D12）。
  - **アルコール値をNULLで登録** → 点呼記録として不完全な見え方になるため、施主判断で 0.000 を採用（D14）。
