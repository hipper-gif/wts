# ADR-0016 乗務前点呼も乗務後点呼と同じ形にする（点呼日を選ぶ・替えたら読み直す・修正中は運転者を変えない）

- 状態: accepted（2026-11-26）
- 決めた人: 杉原氏（全画面点検の残りを「①乗務前点呼を乗務後と同じ形に」の順で直す、とタスク台帳で決定）。直し方は Claude 案
- 関連: 全画面点検 A-19 ほか乗務前点呼の行（`docs/investigations/2026-11-18-全画面点検/A-日次の運転者動線.md`）、ADR-0012（乗務後点呼の同じ決定）、ADR-0002（事後登録）、ADR-0013〜0015（測定値・必須の確認項目・アルコール）

## 背景
乗務後点呼は ADR-0012 で直したが、乗務前点呼は古い形のままだった。
- 点呼日が常に「今日」。0時をまたいだ乗務・前日の入れ忘れを画面から登録できない。
- 当日の記録で「修正」を押すと運転者の欄が選べるようになり、別の運転者を選んで保存すると、その人の点呼として登録・上書きされ、元の記録は残った（A-19）。
- 保存の後に再読込すると同じ保存がもう1回走った。弾かれた時の入力の残し方が乗務後点呼と違った（画面側で戻す方式）。
- 修正の保存で、過去日のロックと修正理由をサーバーが確かめていなかった。削除は控えを取らずに消していた。

## 決定
ADR-0012 の決定 2〜5・7 を乗務前点呼にもそのまま当てる。
1. 点呼日を選べる。今日と前日は誰でも新しく登録できる。それより前は管理者だけ。未来の日付は選べない。日付の決まりは `functions.php` の `normalizeDutyCallDate`・`canRegisterDutyCallDate` の1か所に置き、乗務前・乗務後の両方が呼ぶ（規約10）。
2. 過去日の分を新しく登録した時は、備考の頭に「【YYYY-MM-DD 事後登録】」を付ける（ADR-0002 D13）。
3. 運転者か点呼日を替えたら、その人・その日の画面に読み直す。「修正」を押した後は運転者と点呼日を変えられない（A-19）。
4. 修正の保存は、サーバーで過去日のロック（管理者だけ）と修正理由を確かめる。
5. 保存・削除の後は画面を出し直す（再読込で二重に保存しない）。保存が通らなかった時は理由を出し、入れた値をサーバー側で残す。修正の保存が通らなかった時は、修正の続きの形で出す（乗務後点呼も同じにした）。
6. 削除は消す前に控える（`archiveRowsBeforeDelete`）。
7. 今日の画面で、昨日出庫したのに乗務前点呼が無い時は「昨日の分を入力する」を1つ出す。
8. 使用予定車両の推定は、選んだ点呼日の出庫→日常点検→その日までの最後の入庫の順。

## 却下した案
- 乗務前点呼の過去日はシステム管理者だけ: 他社テナントは頼む先が無く、行った点呼の記録が残らない（ADR-0012 と同じ理由）。
- 修正で運転者を替えられるまま、保存時に確かめる: 押す前に止められる。乗務後点呼と同じく、選べなくする。

## 見張り
- 事後登録の件数（`pre_duty_calls.remarks` が「【」で始まる行）。

## 残っていること（この決定の外）
- 運転者が自分で登録した前日分は、その運転者には修正できない（過去日は管理者だけ＝`canEditByDate`）。乗務後点呼も同じ。困る声が出たら見直す。
- 車両は画面に出ないままサーバーが推定する（全画面点検の明細 A の pre_duty_call.php 122-153 の行）。
