# ADR-0008: セッションをテナントごとに分ける（cookie名・cookie path・保存先）

| 項目 | 値 |
|---|---|
| Status | `accepted` |
| 日付 | 2026-09-24 |
| Supersedes | なし（`.user.ini` / `session_check.php` の「全テナント共通 session_wts・PHPSESSID・path=/」の暗黙の前提を置き換え） |
| Superseded-by | なし |
| 関連 | `wts/includes/session_boot.php`・`wts/index.php`・`wts/logout.php`・`wts/includes/session_check.php`・`wts/templates/daily_report.php` |

## Context

全テナントが同じオリジン `tw1nkle.com` に居る（Smiley=`/Smiley/taxi/wts`・Lino=`/wts-tenants/lino`・verify2）。
セッションは cookie 名 `PHPSESSID`・`path=/`・保存先1か所（`xserver_php/session_wts`）で共通だったため、
あるテナントでログインしたブラウザが別テナントの URL を開くと**同じセッションが読まれ、同じ users.id の人としてログインした状態になる**。
2026-09-24 の敵対的検証（HaiGO 他社提供の採点）で指摘され、verify2 の管理者セッションで Smiley のダッシュボードが開くことを実測した。
Lino 提供開始（2026-04-10）からこの構造だった。事故の報告は無いが、たまたま誰もその操作をしていなかっただけ。

## Decision

- `includes/session_boot.php` の `wts_session_boot()` を **`session_start()` の直前に必ず呼ぶ**。配置パス（`APP_BASE_PATH`。未ロードなら `.env` を自分で読む）から鍵を作り:
  1. cookie 名 `WTSSESS_<鍵8桁>`
  2. cookie path `<APP_BASE_PATH>/`
  3. 保存先 `xserver_php/session_wts/<鍵>/`
- 3つとも分ける理由: 名前だけ分けても保存先が同じなら、他テナントの有効な session id を持ち込める（`use_strict_mode` は既知の id を拒めない）。
- Remember Me の cookie は既に `APP_BASE_PATH` の path なので変更なし。トークンはテナントの DB で照合される。

## Consequences

- 配布時に全員が一度ログアウトされる（2026-09-24 17:16 に kinki / lino / verify2 へ配布済）。「ログイン状態を保持」の人は自動で入り直す。
- 配布後の実測: verify2 の admin セッションで Smiley・Lino のダッシュボードを開くと**ログイン画面へ戻る**。
- `.user.ini` の `session.save_path` は残しているが、実行時に `ini_set` で上書きされる（テナントごとのサブディレクトリ）。
- 今後 `session_start()` を新しく書く場所があれば、必ず `wts_session_boot()` を先に呼ぶ。
